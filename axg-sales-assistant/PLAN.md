# AXG Sales Assistant — Implementation Plan

This turns the prototypes + truth-layer JSON into a real system, following the
architecture the Pilot Spec makes non-negotiable. It is the working plan; the
Pilot Spec (`docs/AXG_Sales_Assistant_Pilot_Spec.md`) is the source of intent.

## The one architectural commitment

**Engine vs. content, strictly separated** (Spec §2, §14.1):

- **Engine** — instrument-agnostic logic: apply defaults (customer > default > ask),
  assemble the code, enforce interlocks, run gates, handle deviations, format the
  part number, shape the result. *Write-once.* Knows nothing about mag meters.
- **Content** — the JSON truth layer (`data/*.json`). An instrument's "personality."

A model code is **assembled and validated by code, never generated by an LLM.** The
LLM (added later) does exactly two things: read an email into structured fields, and
phrase a reply from a structured result packet. It never produces a fact.

| 4 | UI + expand to next instrument (EJA) | — | ▶ next |

Phases 1–3 are built. The engine is the deterministic "trust foundation"; the language
layer (Phase 2/3) brackets it — extract before, reply after — so the LLM never produces a
fact. Phase 4 (a Next.js UI wired to the engine, then porting EJA/VY into the same result
contract) is next.

## Phase 1 scope (this deliverable)

A standalone TypeScript library under `engine/`, deliberately **not** wired into
React/Next — the engine must not know a UI exists. For the AXG (pilot instrument):

1. **Typed truth-layer loaders** — read `data/*.json`; parse size table and the
   process-connection size ranges out of the verified JSON (single source of truth).
2. **Defaults + precedence** — customer > Allied default > ask, each value tagged with
   its provenance (`customer` / `default` / `rule` / `provisional`).
3. **Fail-safe `-C`** — explosion-proof held when area is unstated; never inferred down.
4. **Code assembly** — the 16 positions → model code + ERP part number.
5. **Validation (cross-position rules)** — process-connection size ranges + exclusions,
   tungsten small-size exclusion, accuracy-C size restriction, use↔explosion forcing,
   remote-sensor blanks.
6. **Deviation logic** — free / **blocked-with-alternatives** / allowed-with-warning.
7. **Companion items** — AX01C signal cable for remote-sensor builds.
8. **Application gates** — conductivity floor (disqualify/caution/pass), the
   compatibility gate as a *structured escalation* (it flags and routes — it never
   decides compatibility), velocity sizing.
9. **Retrofit fit verdict** — competitor lay-length cross-reference.
10. **Normalized result contract** (Spec §15.4) — a result that can carry a model code,
    computed-sizing outcomes, gates, flags, companion items, and open questions. Shaped
    now so EJA / VY / valves slot in behind the same seam later.

## The result contract (the seam that keeps it extensible)

Every engine returns the same shape (Spec §15.4), so the future renderer and the future
instruments don't force a rewrite:

```
EngineResult {
  instrument, kind,
  modelCode?  { positions[], partNumber, provisional },
  companionItems[], gates[], flags[], questions[], fatal?
}
```

A transmitter uses `modelCode` + `gates`. A valve (later) uses computed-sizing +
assembly + gates. The shape already accommodates both.

## Testing approach — and its honest limit

Tests run on Node's built-in runner against:
- the 4 prototype demo scenarios (known-good reference outputs),
- rule-derived edge cases (illegal combinations that must be rejected).

**Limit:** Spec §10 acceptance wants ≥20 historically-quoted codes and 10 real inquiry
emails. We don't have those yet. The engine is provably self-consistent against the
rules; true production acceptance needs that historical data from Allied.

## Decisions

- **Location:** in this repo under `axg-sales-assistant/`, self-contained. The CRM
  intake form is untouched.
- **No framework yet:** the engine is plain TypeScript. A Next.js UI (matching the
  repo's stack) comes in Phase 4, importing the engine.
- **Zero runtime deps:** Node runs the TypeScript directly; tests use `node:test`.
- **Truth layer stays JSON** (Spec §13) — human-inspectable while still settling.
